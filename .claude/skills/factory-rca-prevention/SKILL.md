# RCA / Prevention

Read the incident record and preserve a timeline with environment and version identities. Separate observations, hypotheses and confirmed causal claims. Compare competing explanations against code, telemetry, reproduction and changes. State which evidence would distinguish unresolved explanations.

Identify the failure mechanism and contributing conditions only to the level the evidence supports. Avoid treating chronology, correlation or a convenient human action as proof of root cause. If access or reproduction is unavailable, produce a bounded partial result with the next evidence needed.

Recommend prevention proportional to impact and recurrence. Prefer a regression test or a correction at the shared failure point before adding broad process. Link each action to the failure it would detect or prevent, its owner, verification and remaining limitations. Use the factory RCA template when available. The phase owner decides follow-up and records it in GitHub.
